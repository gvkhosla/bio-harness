# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Existing TypeScript/Node SDK and SQLite CLI. Implementation choice delegated by the user's instruction to pick priorities and ship: a loopback-only Node server and dependency-free HTML/CSS/JavaScript presentation. Existing CLI and Pi tools remain intact.

## Users

Confirmed immediate audience: Ginkgo leadership evaluating a potential partnership. The user will present the demo within days. Longer-term research users and agent developers are a product hypothesis, not established customers.

## Product Purpose

Connect reviewable scientific intent, approvals, execution evidence, and next decisions. The immediate demo must make the integration opportunity understandable without pretending to operate a laboratory.

## Capabilities and Constraints

Existing SDK supports a synthetic phenotype workflow and manual handoff, not live ordering. Public Ginkgo CFPS results are a separate replay contract, not evidence about living cells. Preserve provenance, original units, flags, and attribution. Demo policies must not be called provider qualification. No private credentials, arbitrary uploads, paid operations, or agent approval authority in the demo UI.

## Evidence on Hand

Public Ginkgo CFPS example return at commit c92353b47a214930f07442aabdb6c3242cc301d0. It includes reported concentrations, fluorescence, sample metadata, and flags. It is a published example, not a newly performed or independently authenticated experiment. No customer endorsements or formal partnership exist in this project.

## Product Principles

- Trace every displayed observation to its source.
- Make uncertainty and refused actions visible.
- Keep public-data replay and synthetic demonstrations distinct.
- Make the demo deterministic, offline, and resettable.

## Operating Context

Inferred for this delivery: desktop browser on a laptop in a meeting room; the same view should remain usable on mobile. Network and model availability must not be required for the core walkthrough. UI is a local presentation/review surface, not multi-user authorization.
